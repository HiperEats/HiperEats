## 3. Decisions made

The six decisions change the way we write the I2 stories, so they were made before we distributed the work.

| # | Topic | Decision |
|---|---|---|
| 1 | Test names | We follow the convention of the TP01 and TP03 slides (`whenX_thenY`), which the professor recognizes, instead of the behaviour names of `AGENTS.md`. There are 3 tests to rename. |
| 2 | TDD as a team rule | We adopt TDD. The tests are written before the code, at least for the business rules (BR): first the commit of the failing tests and then the commit of the code. Those commits are the evidence for practice T6. The rule is written in `AGENTS.md` and in the definition of done of `CONTRIBUTING.md`. |
| 3 | AI review tool on PRs (AI3) | We use Claude Code (GitHub Action), under André's responsibility. A human always approves, and the accepted and rejected findings are recorded in the PR. |
| 4 | Database | PostgreSQL 18, the version of the TP03 Testcontainers, so that the tests use the same engine as production. |
| 5 | Quality gate (Q1, Q2) and dependencies (Q3) | Approved, under Daniel's responsibility. SonarCloud with JaCoCo in CI and the "Sonar way" gate applied to new code (80% coverage, duplication up to 3%, A ratings, hotspots reviewed). The gate is mandatory in the `main` ruleset and blocks the merge. For Q3, a CI step checks the dependencies on every build (OWASP Dependency-Check or dependency-review-action). |
| 6 | Story generated by an agent from the Gherkin (AI4) | US2 (register scooter, BR13), because it is small and has clear boundary values (10th accepted, 11th refused). The agent opens the PR; CI and the human review decide. |
